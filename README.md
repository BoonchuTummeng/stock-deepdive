# Stock DeepDive

ปลั๊กอินสำหรับ **วิเคราะห์หุ้นเชิงลึกจากเอกสารต้นฉบับ** แล้วผลิตเป็นบทความ HTML ภาษาไทย
ใช้ได้ทั้ง **Claude Code** และ **Codex** — ตัวเดียวกัน ติดตั้งคนละคำสั่ง
ใช้เวลาราว **35-45 นาที** ต่อหุ้นหนึ่งตัว

> ตัวเลขนี้มาจากการจับเวลาจริง — ทดสอบกับ TACC (บมจ. ที.เอ.ซี. คอนซูเมอร์) ตั้งแต่ยังไม่มีเอกสารในเครื่อง
> จนได้ไฟล์ `.html` ใช้เวลา **40.6 นาที** ความเร็วจะต่างกันตามจำนวนงวดที่บริษัทยื่นและความหนาของหมายเหตุประกอบงบ

รองรับ **หุ้นไทย** (ดึงจากระบบ iDisc ของสำนักงาน ก.ล.ต.) และ **หุ้นสหรัฐ** (ดึงจาก SEC EDGAR)

---

## สิ่งที่ปลั๊กอินนี้ทำ

1. **ดึงเอกสารที่บริษัทยื่นเอง** — งบการเงินย้อนหลังหลายงวด พร้อม **หมายเหตุประกอบงบ** และแบบแสดงรายการข้อมูลประจำปี
2. **แกะตารางที่ซ่อนอยู่** — หมายเหตุประกอบงบของไทยมักเก็บตัวเลขไว้ในออบเจกต์ Excel ที่ฝังในไฟล์ Word ตัวแปลงทั่วไปมองไม่เห็น สคริปต์ในปลั๊กอินนี้แกะออกมาให้ (บางบริษัทมีเกิน 100 ตาราง)
3. **หาหน้าที่เป็นภาพสแกนใน PDF** — รายงานผู้สอบบัญชีมักถูกพิมพ์เป็นภาพ ถ้าไม่รู้ล่วงหน้าจะเสียเวลาค้นหาสิ่งที่ไม่มีในข้อความ
4. **สร้างตารางข้อเท็จจริงกลาง** — ตัวเลขทุกตัวพร้อมงวด หน่วย ไฟล์ต้นทาง และชั้นความน่าเชื่อถือ
5. **เขียนบทความ 10 ส่วน** โดยหยิบตัวเลขจากตารางนั้นเท่านั้น แล้วตรวจด้วยสคริปต์ว่าไม่มีตัวเลขไหนหลุดออกนอกตาราง

**ผลลัพธ์**: ไฟล์ `.html` ไฟล์เดียว เปิดออฟไลน์ได้ ไม่พึ่งอินเทอร์เน็ต

## วิธีใช้

**Claude Code**

```
/stock-deepdive-lite:deepdive DITTO
```

ถ้าอยากดึงเอกสารอย่างเดียวไม่ต้องวิเคราะห์:

```
/stock-deepdive-lite:fetch DITTO
```

**Codex** — เรียกสกิลด้วย `$` ในประโยคปกติ

```
ใช้ $deepdive วิเคราะห์หุ้น DITTO
ใช้ $fetch ดึงงบของ DITTO มาเก็บไว้
```

> ⚠️ **ฝั่ง Codex อาจใช้เวลานานกว่า** — ขั้นเขียนบทความออกแบบไว้ให้แตกเป็น 3 สายทำพร้อมกัน
> ถ้าเครื่องมือแตก sub-agent ไม่ได้ ระบบจะทำเรียงกันทีละสายแทน เวลารวมจะกลายเป็นราว **60-75 นาที**
> ผลลัพธ์และกฎการตรวจตัวเลขเหมือนเดิมทุกข้อ ต่างแค่เวลา

**หุ้นสหรัฐต้องใส่อีเมลจริงครั้งแรก** — SEC บังคับให้ผู้เรียก API ระบุตัวตน ไม่งั้นบล็อก
ตั้งถาวรด้วยตัวแปรสภาพแวดล้อม `SEC_CONTACT` เช่น `SEC_CONTACT="ชื่อคุณ you@example.com"`

ไฟล์ที่ได้จะอยู่ที่ `./data/<TICKER>/` (เอกสารดิบ) และ `./paper/` (บทความ)

## สิ่งที่ปลั๊กอินนี้ **ทำไม่ได้** — อ่านก่อนใช้

- **ไม่มีบทถอดเทปหรือสไลด์การประชุมนักลงทุน** — แหล่งข้อมูลที่ใช้ไม่มีของพวกนี้ ⇒ ตอบไม่ได้ว่าผู้บริหารถูกถามอะไรแล้วเลี่ยง ถ้าคุณมีไฟล์เอง วางไว้ในโฟลเดอร์ `./data/<TICKER>/` แล้วมันจะอ่านให้
- **ไม่มีราคาหุ้นและมูลค่าตลาด** — เอกสารที่ยื่นหน่วยงานกำกับไม่มีข้อมูลราคา ถ้าจะให้ตีมูลค่า ต้องหาราคามาให้เอง และมันจะติดป้ายว่าเป็นแหล่งรอง
- **ไม่มีขนาดตลาดหรือข้อมูลการเงินของคู่แข่ง** — บริษัทส่วนใหญ่ไม่เปิดเผยไว้ในเอกสารที่ยื่น ⇒ หัวข้อนี้จะเขียนบอกตรง ๆ ว่าไม่มี ไม่เดาแทน
- **ไฟล์ Word/Excel รุ่นเก่า (`.doc`/`.xls`) แปลงไม่ได้** — เป็นไฟล์ไบนารีคนละรูปแบบ ถ้าจำเป็นให้เปิดด้วย Word แล้ว save เป็น `.docx` ไว้ในโฟลเดอร์เดิม
- **ชื่อย่อหุ้นอาจชนกัน** — ระบบ iDisc ครอบคลุมบริษัทที่ออกหุ้นกู้แต่ไม่ได้จดทะเบียนในตลาดด้วย สคริปต์จะพิมพ์ชื่อบริษัทที่เจอออกมาทุกครั้ง **ให้ตรวจก่อนเสมอว่าใช่ตัวที่ต้องการ**

## เวลาที่ใช้จริง

จากการทดสอบกับ TACC ตั้งแต่ยังไม่มีเอกสารในเครื่อง:

| งาน | ใครทำ | เวลาจริง |
|---|---|---|
| ดึงเอกสาร แปลงไฟล์ แกะตารางฝัง หาหน้าสแกน | สคริปต์ | **4.2 นาที** (ส่วนแปลงไฟล์ใช้ไม่กี่วินาที ที่เหลือคือรอดาวน์โหลด) |
| สร้างตารางข้อเท็จจริง | AI 1 ตัว | **6.2 นาที** |
| เขียนบทความ 10 ส่วน | AI 3 ตัวขนานกัน | **23.4 นาที** (สายที่ช้าที่สุด) |
| ประกอบ HTML และตรวจตัวเลข | สคริปต์ | ไม่กี่วินาที |
| **รวม** | | **40.6 นาที** |

การเขียนแบ่งเป็น 3 สายที่ทำงานพร้อมกัน เวลารวมจึงเท่ากับสายที่ช้าที่สุด ไม่ใช่ผลบวกของทุกสาย
สายที่ช้าที่สุดคือสายที่รับผิดชอบงบการเงินและความเสี่ยง ซึ่งหนักกว่าสายอื่นราวสี่เท่า

**สิ่งที่ทำให้เร็วขึ้นได้คือการย้ายงานที่ไม่ต้องใช้การคิดออกไปเป็นสคริปต์** — การแกะไฟล์ แปลง PDF
หาหน้าสแกน และประกอบ HTML ให้ผลลัพธ์เหมือนเดิมทุกครั้ง ถ้าปล่อยให้ AI ทำจะกินเวลาหลายสิบนาทีต่อรอบ

## หลักการที่ระบบนี้ยึด

- **ตัวเลขเข้าบทความได้ทางเดียว** คือผ่านตารางข้อเท็จจริงที่ตรวจกับเอกสารต้นฉบับแล้ว มีสคริปต์คอยตรวจว่าไม่มีตัวไหนหลุด
- **แยกชั้นความน่าเชื่อถือให้เห็น** — เอกสารที่ยื่น ≠ คำพูดผู้บริหาร ≠ พาดหัวข่าว ≠ ข้อมูลตลาดแหล่งรอง สามอย่างหลังต้องติดป้ายเสมอ
- **ข้อมูลที่ไม่มี ต้องเขียนว่าไม่มี** ห้ามเว้นว่าง ห้ามเดา
- **การตีมูลค่าใช้กรอบ "ราคานี้บังคับให้เชื่ออะไร"** ไม่ใช่ "ถูกหรือแพง" เพราะอย่างแรกตรวจสอบได้
- **เจอความผิดปกติ ไม่เท่ากับพิสูจน์เจตนา** — บทความรายงานได้ว่าเห็นอะไรและมันผิดปกติยังไง แต่ไม่สรุปว่าใครตั้งใจทำอะไร

## ข้อจำกัดความรับผิด

บทความที่ได้จากปลั๊กอินนี้เป็น **ข้อมูลประกอบการศึกษา ไม่ใช่คำแนะนำการลงทุน**
ตัวปลั๊กอินถูกออกแบบไม่ให้เขียนว่าควรซื้อหรือควรขาย

เนื้อหาสร้างโดยโมเดลภาษา **อาจผิดพลาดได้** ตัวเลขทุกตัวมีการอ้างอิงไฟล์ต้นทางกำกับไว้
**ควรตรวจกับเอกสารต้นฉบับก่อนใช้ตัดสินใจใด ๆ**

ปลั๊กอินนี้ดึงข้อมูลจากแหล่งสาธารณะที่เปิดให้เข้าถึงฟรีเท่านั้น ไม่ดึงจากแหล่งที่ต้องเสียเงินหรือต้องล็อกอิน
