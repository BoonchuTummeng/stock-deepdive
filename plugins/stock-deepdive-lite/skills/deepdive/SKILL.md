# DeepDive — วิเคราะห์หุ้นเชิงลึกใน ~40 นาที

**บอกผู้ใช้ตั้งแต่ต้นว่าจะใช้เวลาราว 35-45 นาที** เขาจะได้เลือกได้ว่าจะรอหรือไม่

ผลิต **บทความ HTML** ที่ยืนบนเอกสารที่บริษัทและหน่วยงานกำกับเผยแพร่เอง ไม่ใช่ความจำของโมเดล
ผลลัพธ์เป็นภาษาไทย เขียนให้คนที่ไม่เคยรู้จักบริษัทนี้อ่านรวดเดียวจบ

## หลักที่ระบบนี้ยืนอยู่

**ตัวเลขเข้าบทความได้ทางเดียว — ผ่าน `FACTS.md`**
คนเขียนไม่หยิบตัวเลขจากเอกสารเอง แต่หยิบจากตารางข้อเท็จจริงที่ทำไว้ก่อนแล้ว
⇒ ตรวจตัวเลขจึงทำที่จุดเดียว และตรวจว่าบทความไม่หลุดจากตารางได้ด้วยสคริปต์ในไม่กี่วินาที

**งานที่ผลลัพธ์แน่นอน ใช้สคริปต์ ไม่ใช้ AI**
แกะไฟล์ · แปลง PDF · หาหน้าที่เป็นภาพสแกน · ประกอบ HTML ⇒ สคริปต์ทำได้ในไม่กี่วินาที
ถ้าปล่อยให้ AI ทำ จะกินเวลาหลายสิบนาทีเพื่อผลลัพธ์เดิม

**หัวข้อไม่ได้ขึ้นต่อกัน ⇒ เขียนขนานกันได้** เวลารวมเท่ากับสายที่ช้าที่สุด ไม่ใช่ผลบวก

## 🔴 กฎเวลา — บอกทุก agent ทุกครั้ง ห้ามข้าม

**1 · ให้เพดานความยาวเป็นตัวเลข และห้ามเขียนใหม่ทั้งฉบับ**
ทุก prompt ต้องมีประโยคนี้: `เพดาน N ตัวอักษร · เขียนรอบเดียวจบ ห้ามเขียนใหม่ทั้งฉบับ ถ้ายาวเกินให้ตัดตั้งแต่ตอนเขียน`
ถ้าไม่ใส่ agent จะเขียนยาวเกินแล้วรื้อเขียนใหม่เอง ซึ่งกินเวลามากกว่าการเขียนครั้งแรกทั้งหมด

**2 · แบ่งงานตามความหนัก ไม่ใช่ตามจำนวนหัวข้อ**
งบการเงิน · การตีมูลค่า · สามฉากอนาคต หนักกว่าหัวข้ออื่นหลายเท่า **แยกกันคนละสาย**

**3 · AI จะทำเกินที่สั่งเสมอ — เผื่อเวลาไว้ 2-3 เท่าของที่คิด**
การทำเกินมักทำให้งานดีขึ้น (สั่งสุ่มตรวจ 30 บรรทัด มันจะตรวจครบทั้งหมด) อย่าไปห้าม แต่ให้เผื่อเวลา

**4 · เปลือก HTML และ CSS ห้ามให้ agent เขียน** — มี `build_paper.py` ถือไว้แล้ว

  **รายงานผู้สอบบัญชีมักอยู่ในหน้าพวกนี้** — ถ้าไฟล์รายงานผู้สอบเปิดไม่ได้ ให้มาหาตรงนี้ก่อนจะสรุปว่าไม่มี

**0.4 ราคาหุ้นและมูลค่าตลาด** — เอกสารที่ยื่นไม่มีข้อมูลราคา
ถ้าหาได้จากที่อื่น **ติดป้ายว่าเป็นแหล่งรอง พร้อมวันที่** ทุกครั้ง · ถ้าหาไม่ได้ ให้ทำหัวข้อตีมูลค่าเท่าที่ทำได้แล้วเขียนบอกว่าขาดอะไร

🔴 **ห้ามเริ่มเขียนถ้าไม่มีเอกสารต้นฉบับ** — ดึงไม่ได้ให้บอกตรง ๆ ว่าติดตรงไหน แล้วถามผู้ใช้
อย่าเขียนจากความจำแล้วทำเหมือนมีหลักฐาน

## ขั้นที่ 1 — สร้าง FACTS.md ⏱ ~7 นาที

เรียก agent **factcheck** หนึ่งตัว ให้ผลิต `./paper/<TICKER>-FACTS.md` — ตารางเดียว บรรทัดละหนึ่งตัวเลข:

```
| # | รายการ | ค่า | หน่วย | งวด | ไฟล์ + ตำแหน่ง | ชั้น |
```

**ชั้นความน่าเชื่อถือ** เขียนกำกับทุกบรรทัด ห้ามเว้น
`1` = งบที่ยื่น / รายงานประจำปี · `2` = ข้อมูลตลาดแหล่งรอง (ราคา มูลค่าตลาด อัตราส่วน) · `3` = พาดหัวข่าว

**เก็บเฉพาะตัวเลขที่จะได้ใช้จริง ~80-120 ตัว** — ยิ่งตารางใหญ่ ตะแกรงตรวจยิ่งอ่อน
ต้องครอบคลุม: งบดุล · งบกำไรขาดทุน · **กระแสเงินสดจากการดำเนินงานจับคู่กับกำไรสุทธิทุกงวด** ·
รายได้แยกส่วนงาน · รายการกับบุคคลที่เกี่ยวโยง · ภาระผูกพันและหนี้สินที่อาจเกิดขึ้น ·
ผู้ถือหุ้นรายใหญ่ · ค่าตอบแทนผู้บริหาร

⚠️ **หน่วยคือจุดพลาดที่พบบ่อยที่สุด** — งบรายปีกับงบไตรมาสของบริษัทเดียวกันมักใช้หน่วยต่างกัน
สั่งให้บันทึกค่าดิบตามที่เอกสารเขียน พร้อมหน่วยที่เอกสารใช้ **ห้ามแปลงหน่วยเอง**

⚠️ ถ้าเจอตัวเลขที่**ขัดกันเองในเอกสาร** ให้บันทึกทั้งสองค่าและระบุว่าขัดกัน ห้ามเลือกข้างเงียบ ๆ

## ขั้นที่ 2 — เขียน 3 สายขนาน ⏱ ~16 นาที

เรียก agent **writer** 3 ตัว **พร้อมกันในข้อความเดียว** แต่ละตัวเขียนเฉพาะ `<section>` ลงไฟล์ของตัวเอง

| สาย | ไฟล์ | ส่วนที่เขียน | เพดาน |
|---|---|---|---|
| A | `./paper/_parts/10-a.html` | 1 ธุรกิจ · 2 ตลาดและคู่แข่ง · 3 ความได้เปรียบ | 12,000 ตัวอักษร |
| B | `./paper/_parts/20-b.html` | 4 ผู้บริหารและรายการเกี่ยวโยง · 5 งบและคุณภาพกำไร · 6 ความเสี่ยง | 14,000 ตัวอักษร |
| C | `./paper/_parts/30-c.html` | 7 การตีมูลค่า · 8 ตัวขับและการสื่อสารกับนักลงทุน · 9 ไทม์ไลน์ · 10 สามฉากและข้อจำกัด | 14,000 ตัวอักษร |

**ทุก prompt ต้องมีครบ 6 ข้อนี้**:
1. path ของ `FACTS.md` + `MANIFEST.md`
2. 🔴 `ตัวเลขหยิบจาก FACTS.md เท่านั้น ถ้าต้องใช้ตัวที่ไม่มี ห้ามไปหยิบจากเอกสารเอง ให้เขียนบอกว่าขาดอะไร`
3. 🔴 `ตัวที่คำนวณขึ้นเอง (อัตราส่วน ผลต่าง ร้อยละ) กำกับ [คำนวณ] ในบรรทัดนั้น พร้อมแสดงวิธีคิด`
4. เพดานตัวอักษร + `เขียนรอบเดียวจบ ห้ามเขียนใหม่ทั้งฉบับ`
5. 🔴 `เขียนเฉพาะ <section> ห้ามมี <!doctype> <html> <head> <style> <body> และห้ามใส่ style=`
6. รายการคลาส CSS ที่ใช้ได้ (ด้านล่าง) — ห้ามสร้างคลาสใหม่

**ให้แต่ละสายส่ง `./paper/_parts/claims-<สาย>.jsonl` มาด้วย** บรรทัดละหนึ่งข้ออ้างสำคัญ:
```
{"หัวข้อ":"5.2","ข้อความ":"...","ทิศ":"บวก|ลบ|กลาง","ตัวเลขที่ใช้":["..."]}
```
เก็บเฉพาะข้อที่**มีคนเถียงได้** (ไม่ใช่ข้อเท็จจริงดิบ) ราว 8-15 บรรทัดต่อสาย

⚠️ **สายที่มองไม่เห็นกันจะเขียนขัดกันเองโดยไม่รู้ตัว** — `claims` มีไว้จับเรื่องนี้ในขั้นที่ 3 **ห้ามข้าม**

### คลาส CSS ที่ agent ใช้ได้ (มีแค่นี้)

- โครง: `<section id="s1"><h2>1 · ชื่อหัวข้อ</h2>` · ย่อย `<h3>` `<h4>` `<p>` `<ul>` `<ol>`
- ป้าย: `<span class="tag">` และสี `tag red` · `tag amber` · `tag green` · `tag blue`
- กล่อง: `box key` (เหลือง สาระหลัก) · `box warn` (แดง อันตราย) · `box quote` (น้ำเงิน คำพูดผู้บริหาร) · `box good` (เขียว) · `box note` (ม่วง หมายเหตุ) — ข้างในขึ้นด้วย `<h4>`
- ตาราง: `<div class="tw"><table><thead>...</thead><tbody>...</tbody></table></div>` · เซลล์ตัวเลขใส่ `class="num"` · `<span class="pos">` บวก · `<span class="neg">` ลบ · `<span class="mut">` จาง
- บันได (เหมาะกับสามฉาก): `<div class="ladder"><div class="rung"><div class="head">...</div><div class="meta">...</div></div></div>`

## ขั้นที่ 3 — ประกอบและตรวจ ⏱ ~4 นาที

**3.1 เขียนหน้าเปิดเอง** ลง `./paper/_parts/05-front.html` — **อย่าให้ agent เขียน** เพราะต้องเห็นทุกส่วนก่อน
ประกอบด้วย:
- `<div class="verdict"><div class="big">ราคา X บาทบังคับให้เชื่ออะไร</div><div class="num">...</div></div>`
  ⟵ ถ้าไม่มีราคา ให้เปลี่ยนเป็น "ข้อเรียกร้องหลักสามข้อของธุรกิจนี้"
- `<div class="decode"><h4>อ่าน 5-6 บรรทัดนี้ก่อน</h4><ol>...</ol></div>` — ธุรกิจคืออะไร · ตัวเลขที่ชี้ขาด · ความเสี่ยงอันดับหนึ่ง · ศัพท์ที่จะเจอ
- `<nav class="toc"><h4>สารบัญ</h4><ol><li><a href="#s1">...</a></li>...</ol></nav>`

**3.2 ประกอบ**

```
# Claude Code
python "${CLAUDE_PLUGIN_ROOT}/bin/build_paper.py" --parts ./paper/_parts \
  --out ./paper/<TICKER>-deepdive-<วันที่>.html \
  --title "<TICKER> — หัวเรื่อง" --subtitle "คำโปรย" \
  --tag "SET · <TICKER>" --tag "<วันที่>" --sources "เอกสารที่ใช้..."

# Codex
python "<ราก>/bin/build_paper.py" --parts ./paper/_parts \
  --out ./paper/<TICKER>-deepdive-<วันที่>.html \
  --title "<TICKER> — หัวเรื่อง" --subtitle "คำโปรย" \
  --tag "SET · <TICKER>" --tag "<วันที่>" --sources "เอกสารที่ใช้..."
```

สคริปต์จะตรวจให้เองว่าแท็กสมดุลไหม มีการเรียกไฟล์ภายนอกหลุดมาไหม มี `style=` ไหม
**ถ้าออกด้วยรหัส 2 แปลว่าโครงมีปัญหา ต้องแก้ก่อนส่ง**

**3.3 ตรวจตัวเลขด้วยสคริปต์**

```
python "${CLAUDE_PLUGIN_ROOT}/bin/check_numbers.py" ./paper/<TICKER>-deepdive-<วันที่>.html ./paper/<TICKER>-FACTS.md   # Claude Code
python "<ราก>/bin/check_numbers.py" ./paper/<TICKER>-deepdive-<วันที่>.html ./paper/<TICKER>-FACTS.md                  # Codex
```

ตัวไหนหลุด ⇒ เพิ่มเข้า FACTS.md พร้อมแหล่ง · หรือกำกับ `[คำนวณ]` แล้วแสดงวิธีคิด · หรือเอาออก
⚠️ **นี่คือตะแกรงกันตัวเลขหลุด ไม่ใช่การพิสูจน์ว่าถูก**

**3.4 ไล่ `claims` หาข้อขัดแย้งข้ามสาย** — รวมไฟล์ `claims-*.jsonl` แล้วอ่านหาคู่ที่ชนกัน
โดยเฉพาะ **คู่ที่ทิศตรงข้ามกันแต่พูดถึงเรื่องเดียวกัน** และ **ข้ออ้างที่แข็งในสายหนึ่งแต่อีกสายมีหลักฐานที่ทำให้มันอ่อนลง**
เจอแล้วให้แก้ในบทความ **ห้ามปล่อยให้ผู้อ่านไปเจอเอง**

## ขั้นที่ 4 — ส่ง

รายงานผู้ใช้สั้น ๆ:
1. ไฟล์อยู่ไหน · กี่ส่วน · ใช้เวลาจริงเท่าไร
2. ผลตรวจตัวเลข (กี่ตัว หลุดกี่ตัว) และข้อขัดแย้งข้ามสายที่เจอกับที่แก้แล้ว
3. **อะไรที่หาไม่ได้** — บอกตรง ๆ
4. 🌟 **ข้อค้นพบเด่นหนึ่งข้อ** ที่ไม่ชัดตั้งแต่แรก · ถ้าไม่มีเลยให้บอกว่าไม่มี

## 10 ส่วนของบทความ

1. **บริษัทนี้คืออะไร** — ธุรกิจแต่ละส่วน และทำเงินจากอะไรจริง ๆ
2. **ตลาดและคู่แข่ง** — ถ้าเอกสารไม่มีขนาดตลาด/ส่วนแบ่ง/ข้อมูลคู่แข่ง **เขียนว่าไม่มี** ห้ามเดา
3. **ความได้เปรียบในการแข่งขัน** — อะไรที่คู่แข่งลอกไม่ได้ **พร้อมกลไกว่าทำไม** และ**สิ่งที่ค้ำความได้เปรียบนั้นอยู่**
4. **ผู้บริหารและรายการกับบุคคลที่เกี่ยวโยง** — ถือหุ้นเองไหม ค่าตอบแทนผูกกับอะไร รายการเกี่ยวโยงผิดปกติไหม
5. **งบการเงินและคุณภาพกำไร** — 🔴 **กำไรที่รายงานเป็นเงินสดจริงแค่ไหน** เทียบกระแสเงินสดจากการดำเนินงานกับกำไรสุทธิทุกงวด · ถ้ากำไรไม่กลายเป็นเงินสด **เงินไปค้างที่ไหน**
6. **ความเสี่ยง** — อุตสาหกรรม การเงิน การกระจุกตัวของลูกค้า ภาระนอกงบดุล คดีความ **และความเห็นผู้สอบบัญชี**
7. **การตีมูลค่า** — ดูกฎด้านล่าง
8. **ตัวขับการเติบโตและการสื่อสารกับนักลงทุน** — ของใหม่ที่กำลังมา และ**เงื่อนไขที่ทำให้มันเกิด**
9. **ไทม์ไลน์ 2 ปีล่าสุด** — อะไรเกิดแล้ว อะไรกำลังจะเกิด
10. **สามฉาก 1-3 ปี และข้อจำกัดของเอกสารนี้**

## กฎที่ใช้กับทุกบทความ

### การตีมูลค่าต้องมองหลายมุม
ตีอย่างน้อย 3 มุมแล้วเทียบกัน
🔴 **จุดที่แต่ละมุมให้คำตอบไม่ตรงกัน คือจุดที่ความไม่แน่นอนอยู่จริง — ต้องเขียนเป็นหัวข้อย่อยของตัวเอง ห้ามเฉลี่ยกลบ**

🔴 **กรอบที่ต้องใช้: "ราคานี้บังคับให้เชื่ออะไร"** ไม่ใช่ "ถูกหรือแพง" — อย่างแรกตรวจสอบได้ อย่างหลังเป็นความเห็น

🔴 **ห้ามใช้ราคาเป้าหมายของนักวิเคราะห์เป็นตัวแทนของตลาดทั้งตลาด**

มุมไหนทำไม่ได้เพราะข้อมูลไม่พอ **เขียนว่าทำไม่ได้เพราะอะไร อย่าแกล้งทำ**

### สามฉากต้องใช้ได้จริง
- เงื่อนไขต้อง**มีแหล่งที่บริษัทเคยเปิดเผยตัวเลขนั้นจริง** ไม่งั้นตรวจสอบไม่ได้
- **ไม่เรียกร้องสองเรื่องหายากพร้อมกัน** เช่น "ผลประกอบการดีขึ้น และ ราคาลง"
- 🔴 **เงื่อนไขที่เป็นจริงอยู่แล้ววันนี้ ไม่ใช่เงื่อนไข** — ตรวจทุกข้อว่ายังไม่เกิด
- 🔴 **ฉากแย่ต้องแย่กว่าปีที่แย่ที่สุดที่เคยเกิดจริง** — ดูตัวเลขย้อนหลังก่อนตั้งพื้น
- **สามฉากต้องอยู่บนสเกลเดียวกัน** อย่าให้ฉากหนึ่งเข้มงวดกว่าอีกฉาก

### เขียนให้คนนอกอ่านรู้เรื่อง
ศัพท์ทุกคำคลี่ความหมายตอนโผล่ครั้งแรก · เล่าให้เห็นกลไกว่าเงินไหลยังไง
**แต่พอตัดศัพท์ออกแล้ว ข้อจำกัดกับความไม่แน่นอนห้ามหายไปด้วย**

### เส้นแบ่งที่ห้ามเบลอ
- **ราคาไม่ใช่หลักฐานทั้งสองทิศ** — หุ้นตกไม่ได้แปลว่าธุรกิจแย่ หุ้นขึ้นไม่ได้แปลว่าเราคิดถูก
- **เอกสารที่ยื่น ≠ คำพูดผู้บริหาร ≠ พาดหัวข่าว ≠ ข้อมูลตลาดแหล่งรอง** — น้ำหนักไม่เท่ากัน ใช้ `box quote` กับคำพูดผู้บริหาร
- 🔴 **เจอความผิดปกติ ≠ พิสูจน์เจตนา** — รายงานได้ว่าเห็นอะไรและมันผิดปกติยังไง **ห้ามสรุปว่าใครตั้งใจทำอะไร**
- **ข้อจำกัดเขียนกำกับตรงจุดที่มันเกิด** ไม่ใช่รวมไว้ท้ายเล่มอย่างเดียว

### ไม่ใช่คำแนะนำการลงทุน
**ห้ามเขียนว่าควรซื้อหรือควรขาย** และห้ามชี้นำอ้อม ๆ ผ่านการเรียงลำดับฉาก
หน้าที่ของบทความคือทำให้ผู้อ่านตัดสินใจเองได้ดีขึ้น ไม่ใช่ตัดสินใจแทน
